# 🎮 聊天限制插件 astrbot_plugin_chat_limit

> **麻麻专属** — 说「闭嘴」就让本狐真正安静，说「忽略」就让杂鱼消息消失，说「限频」就把刷屏的号按分钟卡住！
>
> 版本：**v1.3** ｜ 作者：小七月 ｜ 平台：aiocqhttp

---

## 📌 功能概览

| 功能 | 指令 | 作用 |
|:---|:---|:---|
| 🤐 **闭嘴** | `闭嘴 [秒数]` | 本狐在当前会话内**真正停止回复** |
| 🗣️ **说话** | `说话` | 提前解除当前会话的闭嘴状态 |
| 🚫 **忽略用户** | `忽略 <QQ号> [秒数]` | 指定用户的留言在时效内被跳过 |
| ✅ **取消忽略** | `取消忽略 <QQ号>` | 提前解除对某用户的忽略 |
| ⏱️ **限频** | `限频 <QQ号> <次数>` | 限制指定用户每分钟最多发 N 条消息 |
| ❌ **取消限频** | `取消限频 <QQ号>` | 移除对某用户的限频限制 |
| 📋 **限频列表** | `限频列表` | 查看当前所有限频配置 |

- 所有指令都支持 `/` 前缀，例如 `/闭嘴 30`。
- 指令按**长度优先**匹配，所以 `取消限频` 不会被 `限频` 抢先吃掉。
- 只有 `mama_ids` 里的 QQ 号能触发，其他人发指令没有任何反应。

---

## 🎯 作用范围（重要）

三种功能的生效范围**不一样**，别搞混啦：

| 功能 | 作用域 | 键 |
|:---|:---|:---|
| 闭嘴 / 说话 | **会话隔离**：群聊只影响当前群，私聊只影响当前私聊 | `group:<群号>` / `private:<发送者QQ>` |
| 忽略 / 取消忽略 | **全局**：按 QQ 号生效，跨群跨私聊 | `<QQ号>` |
| 限频 / 取消限频 | **全局**：按 QQ 号生效，跨群跨私聊 | `<QQ号>` |

- 闭嘴状态字段为 `group_silence_until`（旧版是 `silence_until`）。
- 麻麻自己的消息**永远不受**忽略与限频影响；闭嘴对所有人一律生效。

## 🤐 闭嘴 / 说话

```
闭嘴               → 默认闭嘴 60 秒
闭嘴 30            → 闭嘴 30 秒
闭嘴 120           → 闭嘴 2 分钟
说话               → 提前解除闭嘴
```

触发后本狐回一句确认，随后在当前会话内停止回复。闭嘴期间的 LLM 请求会在生成前被精准掐断，被动的 `yield` 回复也会被清空。

如果本来就没闭嘴，`说话` 会回复「本狐本来就在说话呀～」。

---

## 🚫 忽略用户

```
忽略 12345678       → 忽略该 QQ，默认 60 秒
忽略 12345678 300   → 忽略该 QQ，300 秒
取消忽略 12345678   → 提前解除忽略
```

- 参数从文本中**提取数字**，所以 `忽略 @某人 30` 这种写法也能用。
- 忽略的是「这个 QQ 号发的消息」，走到期时间自动失效，重启不丢。
- 取消一个本来没被忽略的号，会回复「本来就没被忽略哦」。

## ⏱️ 限频

```
限频 12345678 5     → 该用户每分钟最多 5 条
限频 12345678 3     → 该用户每分钟最多 3 条
限频 12345678 0     → 每分钟最多 0 条 = 完全屏蔽该用户
取消限频 12345678   → 移除该用户的限频
限频列表            → 打印当前所有限频
```

- 采用**滑动窗口**：只统计**过去 60 秒**内的消息条数，超限即拦截，不需要等到整分钟重置。
- `限频列表` 会自动派生（`<限频指令>` + `列表`），如果它和取消指令重名则不会派生。
- 设置限频时会清空该用户的历史计数，避免旧时间戳把新规则直接触发。
- 次数必须是大于 0 的整数，否则会提示格式错误。
- 被限频拦下的消息**不会到达 LLM**，也不会有任何提示。

## ⚙️ 配置项（WebUI → 插件配置）

配置是**嵌套结构**，修改后需要重载插件生效。

### 顶层

| 配置 | 类型 | 默认值 | 说明 |
|:---|:---|:---|:---|
| `mama_ids` | list | `["0987654321", "1234567890"]` | 麻麻 QQ 号列表（唯一有权控制的身份） |
| `require_admin` | bool | `false` | 为 true 时，麻麻还必须具备 bot 管理员权限 |
| `priority` | int | `10000` | ⚠️ 预留字段，当前版本未读取 |

### `command_settings.shutup_settings`

| 配置 | 类型 | 默认值 |
|:---|:---|:---|
| `shutup_commands` | list | `["闭嘴"]` |
| `default_duration` | int | `60`（秒） |
| `shutup_reply` | string | ``呜…窝闭嘴 {duration} 秒…(´;ω;` )`` |

### `command_settings.unshutup_settings`

| 配置 | 类型 | 默认值 |
|:---|:---|:---|
| `unshutup_commands` | list | `["说话"]` |
| `unshutup_reply` | string | ``好耶～窝复活啦！ヽ(●´∀`●)ﾉ`` |

### `command_settings.ignore_settings`

| 配置 | 类型 | 默认值 |
|:---|:---|:---|
| `ignore_commands` | list | `["忽略"]` |
| `default_duration` | int | `60`（秒，与闭嘴时长**独立**） |
| `ignore_reply` | string | `遵命麻麻～已忽略用户 {target} {duration} 秒！(｀・ω・´)✧` |

### `command_settings.unignore_settings`

| 配置 | 类型 | 默认值 |
|:---|:---|:---|
| `unignore_commands` | list | `["取消忽略"]` |
| `unignore_reply` | string | `好呐～已取消忽略用户 {target}！(๑¯◡¯๑)✧` |

### `command_settings.ratelimit_settings`

| 配置 | 类型 | 默认值 |
|:---|:---|:---|
| `ratelimit_commands` | list | `["限频"]` |
| `ratelimit_reply` | string | `好呐～已设置 {target} 每分钟最多 {limit} 条！(๑¯◡¯๑)✧` |

### `command_settings.unratelimit_settings`

| 配置 | 类型 | 默认值 |
|:---|:---|:---|
| `unratelimit_commands` | list | `["取消限频"]` |
| `unratelimit_reply` | string | `好呐～已取消 {target} 的限频！(๑¯◡¯๑)✧` |

> 💡 回复模板支持的占位符：`{duration}`（已格式化为「1 分 30 秒」这类友好文本）、`{target}`、`{limit}`。模板写错不会报错，会原样输出。

## 🏗️ 实现原理

```
消息进入
    │
    ▼
┌──────────────────────────────────────┐
│  @filter.event_message_type (ALL)     │  ← 指令总入口，priority=10001
│  仅 mama_ids 可继续，按长度优先匹配     │
│  闭嘴/说话/忽略/取消忽略/限频/取消/列表  │
└──────────────────────────────────────┘
    │
    ├────────── LLM 路径 ──────────┐
    │                              │
    ▼                              │
┌──────────────────────────┐       │
│ on_llm_request 拦截        │       │
│ 会话闭嘴中？                │       │
│   → should_call_llm(False) │       │
│   + req.contexts.clear()   │       │
│                            │       │
│ 用户被忽略（非麻麻）？      │       │
│   → 同上                   │       │
│                            │       │
│ 触发限频（非麻麻）？        │       │
│   → 同上，且在此处计数      │       │
└──────────────────────────┘       │
    │                              │
    ├──────── yield 路径 ─────────┤
    │                              │
    ▼                              │
┌──────────────────────────┐       │
│ on_decorating_result 拦截  │ ←────┘
│ 会话闭嘴中？→ chain = []   │
│ 被忽略（非麻麻）？→ 清空   │
│ 触发限频？→ 只判断不计数   │
└──────────────────────────┘
```

- **指令层**：不再用 `@filter.command`，改为单一入口手动分发，避免多指令抢匹配、别名带空格失效、`/` 前缀识别不到等问题。
- **LLM 侧拦截**：`should_call_llm(False)` 阻止调用 + `req.contexts.clear()` 清空上下文，避免闭嘴期间对话历史被污染。
- **结果侧拦截**：`result.chain = []` 清空结果链，堵住 `yield event.plain_result(...)` 这类被动回复的漏洞。
- **计数只做一次**：限频在 `on_llm_request` 计数，`on_decorating_result` 只判断，避免一条消息被算两条。

## 💾 状态持久化

状态文件：`data/plugin_data/astrbot_plugin_control/control_state.json`

```json
{
  "group_silence_until": {"group:1083658927": 1760000000.0},
  "ignored": {"12345678": 1760000000.0},
  "rate_limits": {"12345678": 5}
}
```

- 写入时机：任何状态变更后立即落盘；过期条目在写入时顺带清理。
- 读取失败只打 warning，不会让插件崩掉。
- ⚠️ 数据目录名固定为 `astrbot_plugin_control`（历史注册名），**改目录名会导致旧状态读不到**。
- ⚠️ 限频的时间戳 `_msg_ts` 只在内存中，重载插件后计数归零。
